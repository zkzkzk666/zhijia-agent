# SOTIF 与 ODD

## SOTIF（ISO 21448）是什么

- 面向**预期功能安全**：处理**没有电子电气故障**、但因功能**性能不足**、**规范不足**或**可预见的误用**而带来的风险。
- 典型场景：感知漏检（雨雾/逆光/异形车）、规控决策激进、传感器能力边界外的工作、驾驶员误用（过度依赖）。

## 与 ISO 26262 的边界

| 维度 | ISO 26262 | ISO 21448（SOTIF） |
| --- | --- | --- |
| 关注点 | 电子电气故障 | 功能/性能不足、规范不足、误用 |
| 典型对象 | 安全机制、硬件失效、软件缺陷 | 感知/决策算法的能力边界 |
| 输出 | 安全目标、ASIL、安全机制 | SOTIF 验收准则、触发条件分析、安全措施 |
| 方法论 | HARA、FMEA、FTA | 场景分析、触发条件（Triggering Conditions） |

两者必须**同时满足**：无故障时不能因功能不足造成风险，有故障时要有安全机制兜底。

## ODD（运行设计域）

- **定义**：运行自动驾驶系统所需的条件集合——道路类型、速度范围、天气、光照、交通状况、地理围栏等。
- **设计要点**：
  1. 明确可用条件并**可量化**（如：高速公路 ≤120km/h、无雨雪、白天/夜间均可、无施工封路）；
  2. 明确每项条件的数据来源与传感器能力是否覆盖；
  3. 明确**超 ODD 时的处理**：降级功能或安全退出；
  4. ODD 与 SOTIF 验收强关联：只在 ODD 内宣称能力。
- **示例矩阵**：道路类型 | 速度区间 | 天气 | 光照 | 交通密度 | 特殊场景 | 允许/禁止。

## 触发条件分析（Triggering Conditions）

- 识别使系统在预期内但结果不当的**场景组合**：如「隧道出口 + 强逆光 + 白色车辆」。
- 方法：场景库遍历、实车 + 仿真数据挖掘、事故/误用案例回注。

## SOTIF 验收准则

- 明确「不可接受风险」的量化阈值（如错误 AEB 触发率 ≤ x/百万公里）。
- 定义充分覆盖的**场景库**（功能、失效、误用三类）与覆盖度指标。
- 用仿真 + 实车 + 数据回放三角验证，持续迭代到风险可接受。

## 工程落地

- 建立「场景 → 功能行为 → 触发条件 → 措施 → 验证」闭环。
- SOTIF 分析产物与 26262 产物统一纳入配置与版本管理。
